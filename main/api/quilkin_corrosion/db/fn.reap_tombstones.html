Collects the CRDT bookkeeping left behind by deleted rows.

cr-sqlite keeps a sentinel row in <table>__crsql_clock for every row ever deleted, so that a delete can still win against a concurrent write from a peer that has yet to see it, and a matching entry in <table>__crsql_pks. Neither is ever removed: under row churn the base table stays flat while those two grow without bound, which is what eventually exhausts the volume. Once retention has passed every peer has long since converged and the tombstone is only taking up space.

Deletes at most limit tombstones, plus any primary keys orphaned by an earlier pass. Returns the (tombstone, primary key) row counts. The clock tables are internal to cr-sqlite and carry no triggers, so this does not itself produce a change to gossip.
